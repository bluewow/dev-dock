# PRD 작성 가이드

`/auto:auto-pilot` 커맨드에 입력할 PRD 작성 가이드입니다.
PRD를 하나씩 추가하면서 점진적으로 제품을 완성할 수 있습니다.

## 사용법

```bash
/auto:auto-pilot docs/prd/feature-a.md        # 최초 실행 (신규)
/auto:auto-pilot docs/prd/feature-b.md        # 기능 추가 (점진적)
/auto:auto-pilot resume                        # 중단된 작업 이어하기
```

---

## 템플릿

```markdown
# [프로젝트/기능명]

## 배경
왜 이걸 만드는지. 어떤 문제를 해결하는지.
현재 상황과 불편한 점.

## 목표
이 기능이 완성되면 어떤 상태가 되어야 하는지.
- 목표 1
- 목표 2

## 핵심 기능
우선순위 순서로 나열.

### 1. [기능명]
- 설명: 무엇을 하는 기능인지
- 동작: 유저가 어떤 행동을 하면 어떤 결과가 나오는지
- 조건: 엣지 케이스, 제약 사항

### 2. [기능명]
- 설명: ...
- 동작: ...
- 조건: ...

## 기술 제약 (있으면)
- 사용해야 하는 라이브러리/프레임워크
- 지켜야 하는 성능 기준
- 호환성 요구사항
- 연동할 외부 API/서비스

## 범위 밖 (선택)
이번에 하지 않을 것. AI가 과잉 구현하는 걸 방지.
- 하지 않을 것 1
- 하지 않을 것 2

## 참고
와이어프레임, 스크린샷, 참고 서비스 링크 등
```

---

## 각 섹션의 역할

| 섹션 | 에이전트에게 주는 효과 |
|------|----------------------|
| **배경** | "왜"를 이해해서 의사결정 시 방향 잡음 |
| **목표** | Sprint 분할의 기준점 |
| **핵심 기능 + 동작/조건** | 구현 스펙이 명확해서 온보딩 Q&A가 줄어듦 |
| **기술 제약** | 자율주행 시 잘못된 기술 선택 방지 |
| **범위 밖** | 과잉 구현 방지 (가장 중요) |

---

## 작성 팁

- **"범위 밖"을 반드시 작성하세요.** AI는 관련 기능을 확장하려는 경향이 있어서, 하지 않을 것을 명시하면 Sprint가 깔끔하게 나뉩니다.
- **핵심 기능의 "동작"을 구체적으로 쓰세요.** "유저가 X를 하면 Y가 된다" 형태가 가장 좋습니다.
- **기술 제약은 강한 선호만 적으세요.** 없으면 AI가 프로젝트 패턴에 맞춰 자율 결정합니다.

---

## 점진적 추가 시 팁

두 번째 PRD부터는 `## 기존 기능 연관` 섹션을 추가하면 기획자 리뷰가 더 정확해집니다:

```markdown
# 알림 기능

## 배경
피팅 결과나 투표 결과를 놓치는 경우가 많다

## 핵심 기능
- 피팅 완료 알림
- 투표 결과 알림 (내가 만든 투표에 N명 참여 시)

## 기존 기능 연관
- 헤더의 알림 아이콘(이미 구현됨)과 연결
- 투표 결과 페이지에서 알림 설정 추가
```

| 섹션 | 필수? | 에이전트에게 주는 효과 |
|------|:-----:|----------------------|
| **기존 기능 연관** | 선택 | 기존 코드와의 충돌/의존성을 빠르게 파악 |

안 써도 auto-pilot이 `plan.md`와 기존 코드를 읽어서 파악하지만, 적어주면 더 정확하고 빠릅니다.

### 파일 네이밍

`docs/prd/` 디렉토리에 자유롭게 저장:

```
docs/prd/
  2026-03-06-idea              # 날짜 + 키워드
  2026-03-07-notifications.md  # 날짜 + 기능명
  search.md                    # 기능명만
```

## 예시 — 신규 (전체 기능)

```markdown
# 사내 휴가 관리 시스템

## 배경
현재 휴가 신청을 엑셀로 관리하고 있음.
팀장이 이메일로 승인하는 방식이라 누락이 잦고, 잔여 연차 파악이 어려움.

## 목표
- 직원이 웹에서 휴가를 신청하고 승인 결과를 실시간으로 확인
- 팀장이 한 화면에서 팀원 휴가를 승인/반려
- 잔여 연차가 자동 계산됨

## 핵심 기능

### 1. 휴가 신청
- 설명: 직원이 휴가 유형, 기간을 선택하여 신청
- 동작: 날짜 선택 → 사유 입력(선택) → 제출 → 팀장에게 알림
- 조건: 잔여 연차 부족 시 신청 불가, 과거 날짜 신청 불가

### 2. 승인/반려
- 설명: 팀장이 팀원의 휴가 신청을 승인 또는 반려
- 동작: 대기 목록에서 선택 → 승인/반려 → 신청자에게 알림
- 조건: 반려 시 사유 필수

### 3. 연차 현황 대시보드
- 설명: 본인의 총 연차, 사용, 잔여를 한눈에 확인
- 동작: 로그인 후 메인 화면에 표시
- 조건: 올해 기준, 월별 사용 내역 포함

### 4. 팀 캘린더
- 설명: 팀원들의 휴가 일정을 캘린더로 조회
- 동작: 월간 캘린더에 승인된 휴가 표시
- 조건: 본인 팀만 표시

## 기술 제약
- 프론트: Next.js (기존 사내 시스템과 통일)
- 백엔드: Express + PostgreSQL
- 인증: 기존 SSO 연동 (OAuth2)
- 알림: Slack Webhook

## 범위 밖
- 반차/시간 단위 휴가 (2차에서 진행)
- 모바일 앱 (웹 반응형으로 대체)
- 급여 연동
- 관리자(HR) 페이지 (2차에서 진행)

## 참고
- 현재 엑셀 양식: docs/current-form.xlsx
- 기존 SSO 연동 가이드: docs/sso-guide.md
```
