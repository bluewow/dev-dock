# 산출물 규칙

> product-team 에이전트 및 관련 커맨드가 참조하는 공통 산출물 규칙.

---

## 디렉토리 구조

각 워크플로우는 `{DOCS_ROOT}/tasks/` 하위에 **태스크 단위 폴더**로 산출물을 생성한다.

> **경로 규칙 (절대 준수)**:
> - 모든 산출물은 반드시 `{DOCS_ROOT}/tasks/{NNN-slug}/` 하위에 생성
> - `{DOCS_ROOT}` 바로 아래에 태스크 폴더를 만들지 않는다 (예: `{DOCS_ROOT}/point/` 금지)
> - `tasks/` 디렉토리를 건너뛰지 않는다
> - 폴더명은 반드시 `{3자리번호}-{slug}` 형식 (예: `001-login`, `002-dashboard`)
> - slug만 단독으로 폴더명에 사용하지 않는다 (예: `login/`, `point/` 금지)

```
{DOCS_ROOT}/
├── tasks/
│   ├── 001-login/
│   │   ├── context.md            # 리더 스캔 결과 캐시 (팀원 온보딩용)
│   │   ├── plan.html             # 기획 요약 + 화면 플로우
│   │   ├── design.html           # 디자인 시안 (최신)
│   │   ├── design-v1.html        # 반려된 이전 버전 (자동 백업)
│   │   └── spec.md               # 구현 스펙 (승인 시에만 생성)
│   └── 002-dashboard/
│       └── ...
├── data/                          # 사용자 제공 원본 자료
├── history.json                   # 이력 데이터
└── history.html                   # 이력 뷰 (브라우저)
```

---

## 태스크 번호 채번

- `{DOCS_ROOT}/tasks/` 하위 폴더를 스캔하여 기존 최대 번호 + 1로 채번
- 3자리 zero-padding: `001`, `002`, ..., `999`
- 폴더명: `{번호}-{slug}` (예: `001-login`)
- 빈 디렉토리이면 `001`부터 시작
- **검증**: 폴더 생성 전에 경로가 `{DOCS_ROOT}/tasks/{NNN}-{slug}/` 패턴인지 확인

## context.md (리더 스캔 결과 캐시)

- 리더가 팀원 소환 전에 프로젝트를 스캔한 결과를 저장
- **팀원은 이 파일을 읽고 프로젝트를 파악한다** (각자 독립 스캔하지 않음)
- 이미 존재하면 리더는 스캔을 생략하고 재사용
- 개발 워크플로우(3) 진입 시 개발 컨텍스트 섹션이 없으면 보강

### context.md 형식

```markdown
# Context: [태스크명]
> 생성일: [날짜] | 최종 업데이트: [날짜]

## 프로젝트 스택
- Framework: [CLAUDE.md Tech Stack에서 추출]
- Styling: [CLAUDE.md Style Guide에서 추출]
- Database: [해당 시]
- Architecture: [CLAUDE.md Patterns에서 추출]

## 디자인 시스템
- 컬러 팔레트: [기존 팔레트 목록]
- 타이포그래피: [폰트/사이즈 체계]
- 간격 체계: [간격 규칙]
- 기존 UI 컴포넌트: [버튼, 카드, 모달, 폼 등 스타일 패턴]

## 프론트엔드 컨텍스트
- 재사용 컴포넌트: [컴포넌트명]: [경로] (variants, props)
- 공통 훅/유틸: [이름]: [경로] (용도)
- 스타일 토큰: [변수 목록]
- 코딩 패턴: [컴포넌트 구조, 상태 관리, 데이터 페칭 방식]

## 백엔드 컨텍스트
- API 컨벤션: [URL 패턴, 응답 형식, 에러 응답]
- 레이어 구조: [아키텍처 패턴]
- 재사용 서비스/모델: [이름]: [경로] (용도)
- 코딩 패턴: [데이터 모델, 검증, 에러 처리 방식]

## 금지 사항
- 기존 컴포넌트와 중복되는 새 컴포넌트 생성 금지
- 기존 컬러 팔레트/타이포 체계와 충돌하는 값 사용 금지
- 기존 API 네이밍 컨벤션을 벗어나는 엔드포인트 금지
- CLAUDE.md에 명시된 스택 외 다른 프레임워크/라이브러리 임의 도입 금지
```

**참고**: 워크플로우 (1)(2)에서는 디자인 시스템까지만 채우고, (3) 진입 시 프론트/백엔드 컨텍스트를 보강한다.

## plan.html

- Tailwind CDN 단일 HTML 파일
- **반드시 `.claude/commands/dev/plan-template.html`을 Read → `{{PLACEHOLDER}}` 교체로 생성**
- 폰트는 CLAUDE.md Style Guide 참조 (없으면 Pretendard 기본)

### 필수 구성

| 섹션 | 설명 |
|------|------|
| 화면 플로우 | 단계별 흐름도를 CSS/div로 시각화 (텍스트 나열 아닌 플로우차트) |
| 화면 구성 | 핵심 화면 1~2개를 390px 모바일 목업으로 재현 (와이어프레임) |
| 데이터 모델 | 코드 블록으로 타입 정의 표시 |
| 우선순위 | P0/P1/P2 컬러 코딩으로 시각 구분 |

## design.html

- Tailwind CDN 단일 HTML 파일
- **반드시 `.claude/commands/dev/design-template.html`을 Read → `{{PLACEHOLDER}}` 교체로 생성**
- 폰트는 CLAUDE.md Style Guide 참조 (없으면 Pretendard 기본)

### 탭 구조

| 탭 | 내용 |
|----|------|
| 1. 전체 요약 | 긍정/개선 사항 텍스트 + 최종 판정 |
| 2. Before/After | 변경 포인트별 CSS 목업 나란히 비교 |
| 3. 전체 개선안 | 390px 모바일 기준 CSS/div 전체 화면 목업 |
| 4+. 디자이너별 | 각 디자이너 상세 검토 |

### Before/After 비교 (탭 2) 규칙

- 각 변경 포인트를 개별 섹션으로 분리
- 좌: Before (현재 상태 CSS 재현), 우: After (개선안 CSS 재현)
- 변경 부분을 하이라이트 (테두리 또는 배경색 강조)
- 컬러 변경: 스와치 블록으로 비교
- 크기/간격 변경: 실제 크기로 렌더링
- 컴포넌트 변경: 해당 컴포넌트만 추출하여 비교
- 실제 한국어 텍스트 사용 (Lorem Ipsum 금지)
- hover/active 상태 포함

### 워크플로우별 차이

- (1) 신규 기능: Before 없음 → 디자이너별 시안 목업 비교 (탭 전환)
- (2) 기존 기능 개선: Before/After 필수

## spec.md (Claude 작업용)

- 태스크 폴더 내에 사용자 승인 후에만 생성 (**spec.md의 존재 = 승인 완료**)
- 개발 TF가 이 파일을 읽고 구현을 시작한다
- 포함 내용: 컴포넌트 구조, API 엔드포인트, 데이터 모델, 상태 관리, 승인된 디자인 토큰
- 조건부 승인 시 조건/제외 항목도 spec에 명시

---

## 버전 백업 규칙

반려 시 기존 파일을 태스크 폴더 내에서 버전 백업:
- `design.html` → `design-v1.html`로 이동
- 이미 v1이 있으면 `v2`, `v3`으로 증가
- `plan.html`도 동일 규칙 적용
