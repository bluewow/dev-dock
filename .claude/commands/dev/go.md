# Go (구현)

**분석과 계획을 바탕으로 구현합니다.**

## 사전 준비

1. 루트 CLAUDE.md를 읽고 프로젝트 패턴, 컨벤션, 기술 스택 파악
2. CLAUDE.md가 없으면 `/init` 실행 안내 후 중단
3. 멀티 프로젝트인 경우 CLAUDE.md의 Projects 섹션에서 구현 대상 프로젝트 확인
4. 스타일 가이드가 있으면 참조 (경로는 CLAUDE.md에 명시됨)

## 기존 코드 스캔 (구현 전 필수)

구현 시작 전에 관련 영역의 기존 자산을 반드시 파악한다:

### 프론트엔드
1. **컴포넌트 스캔** — 구현 대상과 관련된 기존 컴포넌트 탐색
   - UI 컴포넌트 (Button, Card, Input, Modal 등)
   - 도메인 컴포넌트 (해당 기능 영역의 기존 컴포넌트)
   - 공통 유틸/훅 (useForm, useAuth 등)
2. **스타일 스캔** — 디자인 토큰, CSS 변수, Tailwind 설정 확인
3. **패턴 스캔** — 기존 코드의 구조적 패턴 파악
   - 컴포넌트 파일 구조 (export 방식, props 타입 정의 등)
   - 상태 관리 패턴 (zustand store 구조, context 사용법 등)
   - 데이터 페칭 패턴 (tanstack-query 키 네이밍, 훅 구조 등)
   - 에러 처리 패턴

### 백엔드
1. **API 스캔** — 기존 API 네이밍 컨벤션, URL 패턴, 응답 형식
2. **구조 스캔** — 레이어 패턴 (Controller → Service → Repository), DDD 바운디드 컨텍스트
3. **도메인 스캔** — 재사용 가능한 기존 도메인 모델, 서비스, 리포지토리
4. **패턴 스캔** — DTO/Entity 매핑, 검증 방식, 에러 처리 패턴, 트랜잭션 관리

## Rules

- 코드 수정 가능
- 중간에 멈추지 말고 완료까지
- 문제 발생 시에만 멈추고 보고
- CLAUDE.md에 정의된 패턴/컨벤션을 따를 것
- 완료 후 요약 제공
- **기존 컴포넌트가 있으면 반드시 재사용** (중복 생성 금지)
- **새 컴포넌트는 기존 컴포넌트와 동일한 구조/패턴으로 생성**
- **기존 스타일 토큰 사용, 새 토큰 추가는 최소화**

## Style Guide 체크 (UI 작업 시)

CLAUDE.md에 스타일 가이드 정보가 있는 경우:
1. 디자인 토큰/CSS 설정 파일 읽기
2. 스타일 가이드 문서 읽기
3. 기존 패턴이 있으면 그대로 사용, 없으면 토큰 기반으로 구현
4. 새 컴포넌트 패턴을 만든 경우, 가이드 문서에 추가
