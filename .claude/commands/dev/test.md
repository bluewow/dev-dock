# Test (테스트)

**테스트를 작성하고 실행합니다.**

## 사전 준비

1. 루트 CLAUDE.md를 읽고 프로젝트 기술 스택, 테스트 프레임워크 파악
2. CLAUDE.md가 없으면 `/init` 실행 안내 후 중단
3. 기존 테스트 파일 패턴 확인 (파일명, 폴더 구조, import 방식)

## 기존 테스트 스캔

1. **테스트 디렉토리 탐색** — test/, tests/, __tests__, spec/ 등 프로젝트 관례에 맞는 위치
2. **기존 테스트 패턴 파악**:
   - 파일 네이밍 규칙 (예: `*_test.dart`, `*.spec.ts`, `test_*.py`)
   - 테스트 구조 (group/describe, setUp/tearDown, mock 방식)
   - assertion 스타일 (expect, assert, matcher)
   - 테스트 데이터 관리 방식 (fixture, factory, inline)
3. **대상 코드 분석** — "$ARGUMENTS" 관련 소스 코드를 읽고 테스트 대상 파악:
   - 공개 API / 메서드 목록
   - 분기 조건, 엣지 케이스
   - 외부 의존성 (mock 필요 여부)

## Rules

- 기존 테스트 패턴을 따를 것 (네이밍, 구조, assertion 스타일)
- 단위 테스트 우선, 필요 시 통합 테스트 추가
- 테스트 이름은 행위를 설명하도록 (한국어 허용)
- Happy path + Edge case + Error case 커버
- 불필요한 mock 최소화 — 실제 객체 사용 가능하면 실제 사용
- 테스트 작성 후 반드시 실행하여 통과 확인
- 실패 시 원인 분석 후 수정

## 실행

1. 기존 테스트 패턴에 맞춰 테스트 파일 생성/수정
2. 테스트 실행 (CLAUDE.md Dev Commands 참조)
3. 실패 시 수정 후 재실행
4. 전체 통과 확인
