사용자 시나리오

시나리오 1: 프로젝트 등록
  1. 메인 대시보드에서 "새 프로젝트" 버튼 클릭
  2. 모달에서 프로젝트 이름 + 로컬 경로 입력
  3. 경로 검증 (API로 해당 경로 존재 여부 확인)
  4. docs/ 폴더 자동 스캔하여 초기 데이터 로드
  5. 대시보드에 프로젝트 카드 추가
시나리오 2: 산출물 리뷰
  1. 프로젝트 카드 클릭하여 상세 페이지 진입
  2. 태스크 목록에서 산출물(plan.html, design.html) 확인
  3. 산출물 클릭 시 뷰어 패널이 열림
  4. HTML 파일이 iframe으로 렌더링
  5. 오른쪽 패널에서 승인/반려 + 코멘트 작성
  6. 결정 내용이 history.json에 자동 기록
시나리오 3: 진행 현황 파악
  1. 메인 대시보드에서 전체 프로젝트 상태 한눈에 확인
  2. 각 카드에 최신 태스크 상태, 진행률 표시
  3. 프로젝트 상세 진입 시 타임라인으로 이력 추적
엣지 케이스
  • 잘못된 경로 입력 시 에러 메시지 + 재입력 유도
  • docs/ 폴더가 없는 프로젝트: "산출물 없음" 안내
  • HTML 파일이 깨진 경우: iframe 로드 에러 처리
  • 프로젝트 폴더가 삭제된 경우: "경로 접근 불가" 표시
  • 동일 경로 중복 등록 방지

데이터 모델

projects.json (서버 사이드 파일)

등록된 프로젝트 목록. milestone 프로젝트 루트의 data/projects.json에 저장.

// 저장 경로: {milestone-root}/data/projects.json

interface Project {
  id: string;              // nanoid 또는 slug
  name: string;            // 프로젝트 표시 이름
  path: string;            // 로컬 절대 경로 (예: "C:\\project\\milestone")
  color: string;           // 카드 컬러 (hex 또는 tailwind 이름)
  createdAt: string;       // ISO 8601
  updatedAt: string;       // ISO 8601
}

// projects.json 형식
type ProjectsFile = Project[];

history.json (각 프로젝트의 docs/history.json)

각 프로젝트 경로 내 docs/history.json을 읽어서 표시. 기존 포맷 그대로 사용.

// 경로: {project.path}/docs/history.json

interface TaskLog {
  phase: string;           // "기획" | "디자인" | "승인" | "개발" 등
  status: string;          // "완료" | "승인" | "반려" | "진행중" 등
  date: string;            // YYYY-MM-DD
  note: string;            // 비고
}

interface TaskEntry {
  slug: string;            // "taskflow"
  name: string;            // "TaskFlow - 진행도/TODO 관리 대시보드"
  logs: TaskLog[];
  reviews?: string[];      // 산출물 경로 목록
  spec?: string;           // spec.md 경로
}

// history.json 형식
type HistoryFile = TaskEntry[];

산출물 스캔 결과 (API 응답)

API가 프로젝트 경로의 docs/ 하위를 스캔하여 반환하는 구조.

interface ScannedFile {
  name: string;            // "plan.html"
  path: string;            // "docs/tasks/001-taskflow/plan.html"
  absolutePath: string;    // 서빙용 전체 경로
  type: "html" | "md" | "json" | "other";
  size: number;            // bytes
  modifiedAt: string;      // ISO 8601
}

interface ScannedTask {
  slug: string;            // "001-taskflow"
  files: ScannedFile[];
  hasSpec: boolean;        // spec.md 존재 여부 = 승인 완료
}

interface ProjectScanResult {
  projectId: string;
  tasks: ScannedTask[];
  history: TaskEntry[] | null;  // history.json 파싱 결과
}

API 엔드포인트

GET /api/projects

등록된 프로젝트 목록 조회

응답: Project[] (projects.json 읽기)
POST /api/projects

새 프로젝트 등록

요청 body: { name: string, path: string, color?: string }
검증: 경로 존재 여부 확인 (fs.existsSync), 중복 경로 방지
응답: 생성된 Project 객체
DELETE /api/projects/[id]

프로젝트 등록 해제 (파일 삭제 아님, 레지스트리에서만 제거)

GET /api/projects/[id]/scan

프로젝트의 docs/ 하위 산출물 스캔

동작: docs/tasks/ 하위 폴더 재귀 스캔 + docs/history.json 파싱
응답: ProjectScanResult
GET /api/projects/[id]/file?path=...

산출물 HTML 파일 내용 반환 (iframe 서빙용)

path 쿼리: docs/ 하위 상대 경로
보안: docs/ 밖 경로 접근 차단 (path traversal 방지)
응답: HTML 파일 내용 (Content-Type: text/html)
POST /api/projects/[id]/decision

의사결정 기록 (승인/반려)

요청 body: { taskSlug: string, decision: "승인"|"반려"|"조건부승인", note: string }
동작: 해당 프로젝트의 docs/history.json에 log 추가
GET /api/projects/[id]/validate

프로젝트 경로 유효성 확인 (등록 전 검증용)

응답: { valid: boolean, hasDocs: boolean, message?: string }
